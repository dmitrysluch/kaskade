# ТЗ: постоянные помещения и виртуальные адреса

Статус: реализовано. Формат контента, существующие комнаты и навигационный
каркас TU перенесены; содержательная редактура `00` и будущие stage-версии
остаются отдельными задачами.

Смежные: [[07-оболочка-тз]], [[14-переходы-и-даты-тз]], [карты пролога](11-maps/README.md), [[пролог/черновики/00-редактура-сцены]]. При расхождении старого формата комнат с этим ТЗ действует это ТЗ.

## Модель

| Сущность | Назначение |
|---|---|
| `persistent` | Постоянный адрес помещения, например `tu.dorm-room`; одна строка, не список тегов |
| `stage` | Сценовый срез мира: строка `00`, `01`, `04` и т. п.; не имя текущего файла |
| Общая комната | Постоянное описание, предметы, переходы и ноды помещения |
| Версия для stage | Изменения общей комнаты для одного среза |
| Нода | Состояние помещения или действие внутри собранной версии |
| Виртуальная комната | Результат объединения общей части с версией stage в памяти движка |

Полная идентичность помещения в игре — `(episode, stage, persistent)`, ноды — та же тройка плюс ID ноды. Имена исходных файлов в игровой идентичности не участвуют. Один Markdown может содержать несколько нод.

`persistent` стабилен после выпуска. Его переименование — миграция сейва и всех
виртуальных ссылок, даже если физическое помещение получило новую экранную
подпись. `label` и `target` можно менять без смены идентичности.
ID устойчивых нод тоже становятся частью сейва. Удаление или переименование
такой ноды требует явной миграции `roomStates`; молча открыть `entry` и
повторить эффекты нельзя. Проходные ноды, которые не записываются, этого
ограничения для сейва не создают, но могут оставаться целями ссылок.

`rooms-virt` — виртуальное пространство адресов. Папку и сгенерированные Markdown-файлы создавать не нужно: движок собирает представления и граф в памяти. Источники остаются обычными авторскими Markdown.

## Источники

У каждого `persistent` внутри эпизода не более одной общей комнаты и не более одной версии для каждого stage. Нет версии — используется общая часть; поиска «ближайшего предыдущего номера» нет. Помещение, живущее в одном срезе, разрешено писать одним файлом с `persistent` и `stage`, без общей части: общая часть нужна там, где есть что разделять между срезами.

Пример общей части в `rooms/common-room.md`:

```yaml
---
id: common-room
type: room
persistent: tu.dorm-room
label: комната Марго и Тоби
target: в комнату
items: [00-window, 00-speaker]
exits:
  - persistent: tu.dorm-corridor
---
```

Пример версии в `rooms/04-room.md`:

```markdown
---
id: 04-room
type: room
persistent: tu.dorm-room
stage: "04"
entry: один
---

## один

Тоби нет. На столе письмо.
```

Отсутствующий `stage` означает общую часть. У версии stage объявляется явно, а не извлекается во время игры из `04-`. Stage — строка: ведущие нули и буквенные суффиксы сохраняются. Префикс файла остаётся удобством автора и источником подсказки при миграции.

`entry` необязателен: это именованная входная нода. Без него первоначальный вход — безымянное вступление файла. Повторный вход учитывает сохранённое состояние помещения, как описано ниже.

В комнатах запрещены `date`, `location`, `timeLabel` для даты и карточки перехода. Эти поля принадлежат отдельным файлам `type: transition` по [[14-переходы-и-даты-тз]]. `label` и `target` комнаты остаются: они нужны навигации.

## Объединение

| Часть | Правило |
|---|---|
| `label`, `target`, `entry`, `available` | Значение версии заменяет общее; отсутствующее наследуется |
| `log` | Значение версии заменяет общее; отсутствующее наследуется, по умолчанию `false` |
| `targets` | Объединение по глаголам; версия заменяет значение совпавшего ключа |
| `items` во frontmatter | Общие постоянные предметы + предметы версии, без повторов; затем добавляются предметы активной ноды |
| `exits` | Если список есть в версии, он целиком заменяет общий вместе с локальными подписями; `[]` означает отсутствие выходов |
| Блок `options` | Блок версии целиком заменяет общий; иначе используется общий или стандартный генератор |
| Нода с тем же ID | Версия заменяет ноду целиком: текст, атрибуты, локальные предметы и переходы |
| Новая нода | Добавляется к общей версии |
| Безымянное вступление | Если версия содержит вступление, оно целиком заменяет общее; отсутствие наследует его |
| Зарезервированный `reentry` | Версия заменяет общий фрагмент целиком; отсутствие наследует его |

Строки текстов и списки переходов внутри заменяемой ноды не склеиваются. Замена остаётся на месте исходной ноды; новые ноды добавляются в порядке источника. В каждом исходном файле повтор ID ноды — ошибка.

Общие `items` действительно постоянны во всех срезах. Тоби, приглашение на день рождения и доска с конкретными записями относятся к версии или ноде. Если вещь надо убрать в другом срезе, её сначала переносят из общей части в соответствующие версии. Механизм вычитания и многоуровневое наследование не вводятся.

`available` — булево поле, по умолчанию `true`. `available: false` закрывает помещение в данном срезе; его автоматически сгенерированный выход не показывается. Отсутствующая версия сама по себе не означает закрытую дверь. Видимая табличка закрытой двери остаётся предметом коридора.

## Адреса переходов

Во frontmatter используется существующий `exits` с новым типом адреса:

```yaml
exits:
  - persistent: tu.dorm-corridor
```

Поля одной записи: обязательный `persistent`, необязательные `stage`, `node` и `target`. Первые три — адрес; `target` — локальная подпись выхода, готовое дополнение к фразе генератора ([[13a-локальные-подписи-выходов-тз]]). Других полей у выхода нет. Пример точного адреса:

```yaml
persistent: tu.dorm-room
stage: "04"
node: один
```

В тексте сцен, комнат и маршрутах предметов используется эквивалентная ссылка:

| Markdown | Значение |
|---|---|
| `[[rooms-virt/tu.dorm-room]]` | Вход в помещение в текущем stage |
| `[[rooms-virt/tu.dorm-room#один]]` | Нода `один` в текущем stage |
| `[[rooms-virt/tu.dorm-room:04]]` | Вход в собранную версию stage `04` |
| `[[rooms-virt/tu.dorm-room:04#один]]` | Нода `один` в собранной версии stage `04` |

Канонический формат: `rooms-virt/<persistent>[:<stage>][#<node>]`. `persistent` содержит латиницу, цифры, точки, дефисы; `stage` — латиницу, цифры, дефисы. Двоеточие и `#` — разделители, не части этих идентификаторов. ID нод сохраняют нынешние правила, включая кириллицу. Расширение `.md` виртуальному адресу не требуется.

Резолвер распознаёт `rooms-virt/` до файлового поиска Obsidian. Все четыре формы разрешаются через один механизм с адресами из `exits`.

```markdown
→ вернуться в комнату [[rooms-virt/tu.dorm-room]]
→ [[rooms-virt/tu.dorm-room:04#один]]
```

Якорь ищется **после объединения**, а не только в файле версии. `[[#один]]` внутри общей или сценовой части комнаты тоже относится к собранной комнате. Аналогичные локальные ссылки внутри сцен и предметов остаются локальными для этих файлов.

Физические ссылки `[[rooms/04-room#один]]`, короткие `[[04-room]]` и адреса `{room: 04-room}` больше не являются игровыми переходами. Они обходили бы объединение. Обычные документальные ссылки на исходники в ТЗ допустимы.

## Stage, дата и монтаж

Активный stage хранится в игровом контексте. Вход в общий файл, осмотр старого предмета или разговор `06-*` не меняют его по префиксу ID.

Только явный `transition` устанавливает stage и дату. Обычный `exits` или маршрут сцены может явно назвать stage, но он должен совпадать с активным. Попытка перейти в другой stage напрямую — ошибка, а не скрытая монтажная карточка. Резолвер может собрать другую версию для валидатора или `/adm` без перемещения игрока.

В `05 ⇄ 06` используется один stage `05`: выход за бланком и возвращение к Алерсу не создают новый день и не сбрасывают комнаты. Префикс `06-*` остаётся номером сюжетного блока. `03a` не преобразуется в число `03`: принадлежность вечера к срезу задаётся явным переходом.

Условия получения ключа остаются на действии перед переходом. Например, «лечь спать» проверяет `word:word-only-case`, затем ведёт в отдельный переход к 01, а не сразу в другую версию аудитории.

## Вход, состояние и опции

- Без `#node` движок использует вход помещения с учётом состояния в текущем stage. Он не начинает безусловно с первого заголовка при каждом возвращении.
- Явный якорь означает намеренный вход в эту ноду; его `if` и доступность проверяются. Если такой ноды нет, переход ошибочен — подмены входной нодой нет.
- Сохранённая нода помещения — последнее устойчивое состояние, а не проходной узел вроде выбора места или вручения коробки.
- При восстановлении экрана не повторяются уже выполненные `give`, `take`, `set`, `once` и автоматические сюжетные вклейки. Условия доступных действий пересчитываются.
- Если автор задал входной диспетчер из условных маршрутов, его проверки выполняются при возвращении: изменение инвентаря может открыть реакцию на принесённый учебник. Диспетчер должен учитывать сохранённое состояние и не возвращать ушедшего Тоби.
- Состояние комнаты живёт при уходе в другую комнату, диалог, предмет и оверлей. Новый stage получает собственное состояние; старые локальные ноды не переносятся в него автоматически. Слова и инвентарь сохраняются по своим правилам.
- Лог комнаты, если в итоговом представлении стоит `log: true`, хранится
  отдельно от `roomStates`, под тем же ключом `(episode, stage, persistent)`.
  Буфер активной комнаты сохраняется и без этого поля, но удаляется при уходе.
  Лог восстанавливает только уже показанный поток; входной диспетчер, текущая
  устойчивая нода и доступные опции всё равно вычисляются по правилам ниже.
  Полный контракт — [[07-оболочка-тз]], «Лог контекста и повторный вход».

Точный алгоритм входа без якоря:

1. Собрать комнату для активного stage и проверить `available`.
2. Если входная нода (`entry` либо безымянное вступление) содержит безымянные
   условные маршруты, считать её **диспетчером** и выполнять при каждом входе.
   Диспетчер не содержит текста, эффектов и помеченных опций. Маршруты
   проверяются в порядке файла, включая `if` целевых нод; выполняется первый
   доступный. Поэтому частные условия стоят раньше общих, а безусловный маршрут,
   если он есть, — последним. Набор обязан исчерпывать достижимые состояния.
   Так возвращение с учебником может открыть оклик Тоби, а ушедший Тоби не
   вернётся.
3. Если диспетчера нет и сохранено устойчивое состояние, открыть его.
4. Иначе открыть `entry` или безымянное вступление впервые.

Устойчивой считается нода комнаты, на которой движок действительно вернул
строку ввода и собрал действия. Проходная нода с единственным безымянным
маршрутом исполняет эффекты и продолжение, но сама в `roomStates` не
записывается. Если автоматическая цепочка вернулась в комнату, сохраняется её
последняя интерактивная нода; если ушла в сцену, прежнее устойчивое состояние
остаётся до явного возврата. Цикл из одних безымянных маршрутов — ошибка
валидатора.

Генераторы `идти: exits` и `осмотреть: items` работают с собранным представлением. `label`, `target` и `targets` берутся у разрешённой цели, а у выхода с локальной подписью она важнее их всех ([[13a-локальные-подписи-выходов-тз]]). Условия и `available` проверяются до показа команды. Текущие правила скрытых веток и авторского перекрытия сгенерированной команды сохраняются.

Общие ноды можно кэшировать как определения, но нельзя разделять между stage или сейвами их изменяемое состояние. Развёрнутые опции общей комнаты также должны учитывать stage; одного глобального списка для всех дат недостаточно.

## Сейв, валидатор и инструменты

Добавить в сейв активный контекст из `transition`, адрес текущего помещения/ноды, состояния комнат и логи комнат по `(episode, stage, persistent)`. Контекст, приостановленный открытым предметом или вызванной сценой, хранить тем же логическим адресом и возобновлять неявным `resume` без повторного вступления и `reentry`; отдельной разметки у `resume` нет. Счётчики `used`/`once` комнат привязывать к логической ноде, не к файлу общей части; переименование файла не должно повторно выдавать предметы. Общая и stage-часть пишут в один лог виртуальной комнаты, а не в два лога исходных файлов.

Повысить `saveVersion` вместе с новым контрактом переходов. Breaking-миграция может отклонять старые сейвы с объяснением; не загружать их с угаданной датой и не стирать автоматически. Если реализуется конвертер, он использует явную таблицу старых ID и сохраняет исходную запись до успешной проверки.

Валидатор проверяет:

- единственную общую часть и не более одной версии на `(episode, persistent, stage)`;
- типы полей, существование stage среди явных переходов эпизода и отсутствие временных метаданных в комнатах;
- все виртуальные цели и якоря в **итоговых** представлениях, включая якоря только из общей части;
- прямые переходы на исходники комнат и смену stage без `transition`;
- существование `entry`, отсутствие неоднозначных ID и доступность цели до исполнения;
- корректность входного диспетчера, отсутствие автоматических циклов и
  существование устойчивого состояния после его маршрутов;
- отсутствие тупиков обязательного маршрута; закрытое помещение не считается отсутствующим файлом;
- совпадение текста авторского перекрытия с новой сгенерированной командой после переименования коридоров.

Ошибки содержат логический адрес и исходные файл/ноду. `/adm` показывает граф выбранного stage и происхождение каждой ноды: общая часть или версия. Обход графа работает по виртуальным адресам. Hot reload общей части пересобирает затронутые представления; версии — только соответствующий срез. Невалидная пересборка не подменяется старой комнатой молча.

## Миграция существующих комнат

Таблица фиксирует исходные активные `пролог/rooms` до миграции, не `legacy`.
Игровая идентичность перенесённых комнат теперь задаётся логическим адресом.

| До миграции | Persistent | Версия на первом проходе | Сохранить |
|---|---|---|---|
| `00-room` | `tu.dorm-room` | `00` | Вступление и `#один`; затем редактура 00 отдельным проходом |
| `01-corridor` | `tu.auditorium-gallery` | `01` | Возврат в H 1012 и сюжетный уход в 02 |
| `01-hall` | `tu.h1012` | `01` | `#до`, `#после`, `#пусто`, `#сзади`, `#первый-ряд` |
| `03-corridor` | `tu.faculty-corridor` | `03` | Таблички, номера, телефон, вход в секретариат |
| `03-office` | `tu.secretariat` | `03` | `#стойка`, справка, приглашение и условная коробка |
| `03-flat` | `ahlers.living-room` | `03` | `#перед-столом`, `#коробка`, уход и начало застолья |

В общую часть переносить только фактически неизменное. Например, доска до/после лекции остаётся в нодах 01, конверт дня рождения — в версии 03, а список внутренних номеров меняется между 03 и 05. Наличие `03-` в ID предмета само по себе не мешает его повторному использованию.

Новые помещения TU из [карты](11-maps/tu-campus.md) получают постоянные адреса: `tu.dorm-corridor`, `tu.dorm-kitchen`, `tu.yard`, `tu.canteen`, `tu.library`, `tu.elevator`, `tu.project-admin`, `tu.neighbour-group`, `tu.ahlers-office`, `tu.doctoral-office`. Их неизменные части пишутся один раз. Версии 00/03/03a/04/05 добавляются по таблице карты, а не копированием всех помещений на каждый номер.

Клуб и участок пока остаются сценами. Их не надо превращать в пустые комнаты ради нового формата ссылок. Связи и поставленный характер проходов квартиры сохраняются по [её карте](11-maps/ahlers-flat.md).

| `03-arrival` → `rooms/03-flat#перед-столом` | `rooms-virt/ahlers.living-room#перед-столом` |
| Переходы между днями: 00 → 01, 01 → 02, 02 → 03 | Через отдельные `transitions/*`, не заменой на прямую виртуальную ссылку |

Проверять не только `→`: вход эпизода, `goto`, списки `exits`, явные цели генераторов, возвраты из предметов и вспомогательных сцен, тесты и данные `/adm`. Локальные `[[#узел]]` сохраняются. Ссылки на сцены, предметы, слова и справочник не переименовываются массово.

Перекрытие выхода из аудитории после лекции должно продолжать вести в `01-after-lecture`, а не обходить разговор. При замене подписи «коридор» на «аудиторная галерея» одновременно меняются `target` и авторская команда.

## Порядок работ и приёмка

1. Зафиксировать старый граф, состояния и список ссылок; подготовить таблицу соответствий.
2. Реализовать разбор общей части/версий, merge, `RoomRef`, виртуальные ссылки и явные переходы из [[14-переходы-и-даты-тз]].
3. Перенести шесть существующих комнат и все входящие ссылки. Смена схемы и перенос контента выпускаются вместе: fallback на сырой файл не оставлять.
4. Перенести временные метаданные, обновить сейв, валидатор, `/adm` и тесты.
5. Собрать новую связанную карту TU; её навигационный каркас готов. Наполнение
   новых помещений и редактура `00` идут отдельным содержательным проходом.
   `legacy` не импортировать в реестр активных комнат.

Проверки результата:

- Общая кухня существует одним источником и открывается в разных stage без изменения даты.
- `tu.dorm-room:04#один` использует общие предметы и ноду версии 04; прямого чтения одного `04-room` недостаточно.
- Якорь из общей части доступен в версии; переопределённая нода не сохраняет старые реплики или переходы.
- После ухода Тоби прогулка и перезагрузка не возвращают его; получение книги вне комнаты открывает нужную реакцию при возвращении.
- Возврат после лекции сохраняет доску и отсутствие Алерса; после вручения коробка не появляется вновь.
- `05 ⇄ 06` с походом за бланком не меняет stage, дату и состояние кабинетов.
- Без `word-only-case` сна нет; с ним «лечь спать» ведёт в явный переход, затем в 01.
- Переименование файла общей комнаты или источника версии stage не меняет
  виртуальные ссылки и новый сейв, пока сохранены `persistent` и `stage`.
- Старые игровые ссылки `rooms/*`, временные метаданные комнат и неразрешимые виртуальные адреса дают ошибку сборки.
