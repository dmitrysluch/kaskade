# ТЗ: мини-игра «Распутать мысль»

Смежные: [[07-оболочка-тз]], [[04-стиль-и-звук]], [[05-тексты-и-документы]],
[[10-пролог]], [[пролог/черновики/00-редактура-сцены]]

Первая реализация нужна для самостоятельной подготовки Марго в `00`. Игрок
распутывает граф, а пересечения его нитей переставляют слова в лежащих рядом
текстах. Физику понимает Марго; игрок решает короткую пространственную задачу и
видит, как из шума складывается прочитанное.

---

## Решение

Новый тип контента:

```yaml
type: minigame
subtype: untangle
```

Подтип называется `untangle`, а не `threads`: `untangle` описывает правило,
которое исполняет движок. Нитями могут быть нарисованы записи Марго, провода или
причинные связи; для механики это одна задача. Поле `threads` остаётся в YAML и
называет конкретные рёбра этого представления.

В первой версии один файл `type: minigame` содержит **одно поле**. Три этапа
подготовки — три файла: два запускаются из учебника, третий — из компьютера.
Это позволяет между ними ставить обычные
флаги, монтажные кадры и возвращение в комнату, не создавая внутри мини-игры
вторую систему сцен.

Мини-игра рендерится обычными HTML/CSS и SVG внутри React. ASCII для графа не
требуется: линии должны двигаться непрерывно между дискретными положениями, а их
пересечения — вычисляться геометрически. Палитра, шрифт, фон и темп берутся у
активного рендерера эпизода.

## Игровой цикл

На экране десять пронумерованных точек и двенадцать соединяющих их нитей. Рядом
лежат один или несколько коротких Markdown-текстов. Пока нити пересекаются,
слова в текстах переставлены.

1. Игрок нажимает цифру `0`–`9` и выбирает точку.
2. Связанные с точкой нити получают разные цвета. Теми же цветами и номерами
   отмечаются соответствующие позиции в тексте.
3. `WASD` или стрелки двигают точку на одну клетку дискретной сетки.
4. Каждое появившееся или исчезнувшее пересечение транспонирует две текстовые
   позиции. Если за шаг изменились несколько пересечений, применяются несколько
   таких локальных обменов.
5. Когда пересечений не осталось, текст принимает исходный порядок. Поле
   блокируется, появляется `Enter`, и игрок может спокойно прочитать результат.
6. Новое нажатие `Enter` исполняет узел завершения из того же файла.

Смысла текста для решения не требуется. Условие победы только геометрическое:
граф должен быть нарисован без пересечений и наложений. Любая корректная
планарная раскладка принимается; попадать в авторское решение не нужно.

Нет таймера, очков, числа ходов, штрафов и Game Over.

## Место в контенте

В эпизод добавляется отдельная папка:

```text
content/episodes/prolog/
  minigames/
    00-study-definitions.md
    00-study-only-case.md
    00-study-ines.md
```

Ссылка на мини-игру использует обычный адрес графа:

```markdown
→ [[minigames/00-study-definitions]]
```

Вход наследует активные `stage`, дату, место и рендерер. Мини-игра не является
комнатой и не меняет левую часть статуса. Прямые ссылки на её служебный узел
завершения запрещены: пройти его можно только решив поле.

Диспетчер `scenes/00-study` остаётся обычной сценой и выбирает одно из двух
книжных полей:

```markdown
→ [[minigames/00-study-only-case]]
  - if: "prolog.study-definitions, !prolog.study-only-case"
→ [[minigames/00-study-definitions]]
  - if: "!prolog.study-definitions"
→ [[rooms-virt/tu.dorm-room]]
```

Флаг `prolog.study-only-case` открывает у компьютера команду
`проверить единственный случай`; она запускает `00-study-ines`. После проверки
флаг `prolog.study-ines` скрывает команду, а `word-only-case` открывает сон.

## Авторский формат

Геометрия задаётся только в YAML-frontmatter, в целых координатах сетки. Текст
задаётся обычным Markdown в теле файла. Пиксельных координат в контенте нет.

Полный пример третьего этапа:

```markdown
---
id: 00-study-ines
type: minigame
subtype: untangle
label: шкала событий
grid: {columns: 24, rows: 18}
seed: 1907
complete: complete
points:
  0: {start: [21, 12], solution: [12, 1]}
  1: {start: [2, 6],   solution: [18, 2]}
  2: {start: [12, 1],  solution: [22, 6]}
  3: {start: [8, 16],  solution: [21, 12]}
  4: {start: [12, 9],  solution: [16, 16]}
  5: {start: [22, 6],  solution: [8, 16]}
  6: {start: [6, 2],   solution: [3, 12]}
  7: {start: [16, 16], solution: [2, 6]}
  8: {start: [3, 12],  solution: [6, 2]}
  9: {start: [18, 2],  solution: [12, 9]}
threads:
  - {id: 0,  points: [0, 1]}
  - {id: 1,  points: [1, 2]}
  - {id: 2,  points: [2, 3]}
  - {id: 3,  points: [3, 4]}
  - {id: 4,  points: [4, 5]}
  - {id: 5,  points: [5, 6]}
  - {id: 6,  points: [6, 7]}
  - {id: 7,  points: [7, 8]}
  - {id: 8,  points: [8, 0]}
  - {id: 9,  points: [9, 0]}
  - {id: 10, points: [9, 3]}
  - {id: 11, points: [9, 6]}
---

### Результат поиска

**INES 7 — крупная авария**

Событий, получивших окончательную оценку 7: **2**.

## complete
- tag: montage
- set: prolog.study-ines
- give: word-only-case
- timeLabel: за полночь

Ты берёшь учебник, обводишь строку и ставишь на поле двойку.

Их два.

→ [[rooms-virt/tu.dorm-room]]
```

Координаты `solution` нужны валидатору и тестам. Они не являются единственным
ответом, не используются при проверке победы и не передаются клиенту. Реализовано
одной развилкой: `/api/content` и ws отдают сборку без `solution`, а там, где
включён `ADM`, — вместе с ней, иначе служебный просмотр не смог бы показать
авторскую раскладку. В
приведённом `start` 23 пересечения, а перестановка затрагивает все двенадцать
позиций первого текстового блока.

### Поля frontmatter

| Поле | Формат | Правило |
|---|---|---|
| `id` | строка | Стабильный ID, совпадает с именем файла |
| `type` | `minigame` | Новый тип игрового узла |
| `subtype` | `untangle` | Единственный подтип первой версии |
| `label` | строка | Короткое название поля в интерфейсе и `/adm` |
| `grid` | `{columns, rows}` | Размер логической сетки; оба значения — положительные целые |
| `seed` | целое | Стабилизирует соответствие нитей и текстовых позиций |
| `complete` | ID узла | Локальный `##`-узел, который исполняется после победы и `Enter` |
| `points` | отображение `0..9` | Начальная и одна проверочная решённая координата каждой точки |
| `threads` | список | Двенадцать нитей с постоянными ID и двумя концами |

В первой версии точек ровно десять, их ID всегда `0`–`9`, нитей ровно
двенадцать, их ID всегда `0`–`11`. Это часть формата, а не настройка уровня:
цифра напрямую выбирает точку, а одинаковая плотность нужна для предсказуемой
сложности трёх этапов.

Координата `[x, y]` адресует клетку. `[0, 0]` — левый верхний угол, `x` растёт
вправо, `y` вниз. `start` — состояние при первом входе, `solution` — известная
автору корректная раскладка.

ID нити постоянен. Перестановка строк в `threads` не должна менять результат:
вычисления сортируют нити по `id`, а не по положению в YAML.

### Markdown-тексты

Текст мини-игры находится до первого заголовка `##`. Каждый заголовок `###`
начинает отдельный документ; его видимый текст служит подписью и не
перемешивается. В первой версии нужен хотя бы один документ, практически для
учебника — два: сама книга и материал, с которым её сверяют.

В документе допустимы абзацы и обычная строчная Markdown-разметка: акцент,
обратные кавычки и явные ссылки на справочник. Списки, таблицы, цитаты,
изображения, HTML, заголовки глубже `###` и игровые маршруты внутри документа
запрещены. Всё после первого `##` разбирается обычным сценическим парсером и в
мини-игру не входит.

Перемещаемая единица — видимое слово:

- обычный текст делится по Unicode-пробелам;
- запятая, точка, тире и другая прилегающая пунктуация остаются со словом;
- неразрывный пробел не делит единицу;
- inline-code и wiki-ссылка являются одной единицей даже при пробеле внутри
  отображаемой подписи;
- акцентная разметка сохраняется на каждом получившемся слове.

Пустые строки разделяют абзацы. Порядок абзацев, заголовки и подписи документов
не меняются.

## Соответствие текста нитям

Пусть в поле `E = 12` нитей. Каждый абзац делится в исходном порядке на полосы
по `E` слов. Последняя полоса может быть короче.

Для каждой полосы отдельно строится детерминированное случайное соответствие:

1. Строка `<id>\0<seed>\0<document>\0<paragraph>\0<band>` хешируется
   `FNV-1a` в беззнаковое 32-битное число.
2. Число инициализирует `mulberry32`; ID нитей перемешиваются обычным
   `Fisher–Yates` от последнего элемента к первому.
3. Первое слово полосы получает первую нить, второе — вторую и так далее.
4. В неполной последней полосе используются только первые `N` нитей полученной
   перестановки.

Индексы документа, абзаца и полосы начинаются с нуля. Арифметика `FNV-1a` и
`mulberry32` выполняется как JavaScript `uint32`; серверный валидатор и клиент
используют одну общую реализацию. Соответствие не меняется от хода к ходу и не
хранится в сейве. Изменение алгоритма требует поднять `saveVersion`, как
изменение другого формата контента.

Текущая версия текста всегда вычисляется заново из авторского оригинала:

```text
слова = копия исходной полосы

для каждой пересекающейся пары нитей (a, b), по возрастанию (a, b):
    если обе нити представлены в этой полосе:
        поменять местами их текстовые позиции
```

Нельзя применять обмены к уже показанному тексту по событиям
`intersectionAdded` и `intersectionRemoved`: результат тогда начинает зависеть
от истории ходов и после распутывания может остаться перемешанным. Одинаковая
геометрия обязана всегда давать одинаковый текст.

Уменьшение числа пересечений не обязано делать каждую промежуточную фразу
понятнее. Геометрия показывает прогресс, текст реагирует локально и полностью
собирается только при победе.

## Геометрия

Точки стоят в центрах клеток. Нить — прямой отрезок между центрами двух точек.
Ломаных, автоматической трассировки и привязки нити к краям кружка в расчётах
нет; визуально линия может обрываться под диском точки.

Пересечением считается собственное пересечение внутренних частей двух
отрезков. Общий конец двух нитей — нормальное соединение и пересечением не
является.

Решение корректно, когда одновременно выполнено всё:

- собственных пересечений нет;
- две точки не занимают одну клетку;
- точка не лежит на чужой нити;
- две нити не лежат друг на друге и не имеют общего участка.

Попасть точкой на занятую клетку нельзя: ход отклоняется. Поставить точку на
чужую нить или создать наложение нитей можно, но такое состояние подсвечивается
как некорректное и не считается победой. Это не должно создавать невидимую
стенку во время распутывания.

Проверка выполняется после каждого принятого дискретного шага. Пересечение трёх
нитей в одной геометрической точке считается попарно: это три пересечения.

## Рендерер

Мини-игра занимает место потока и ввода целиком. Статус с текущим местом и датой
остаётся сверху; история терминала, командная строка, список опций, линейки и
контекстные панели на время игры скрыты.

Основная раскладка на широком экране:

```text
┌─────────────────────────────┬──────────────────────────────┐
│ 10 точек · 12 нитей         │ УЧЕБНИК                      │
│ пересечений: 15             │ перемешанный Markdown        │
│                             │                              │
│       граф на сетке         ├──────────────────────────────┤
│                             │ СПРАВОЧНИК                   │
│                             │ перемешанный Markdown        │
│                             │                              │
│ точка 3 · нити 02 03 10     │                              │
└─────────────────────────────┴──────────────────────────────┘
  0–9 точка · WASD/стрелки двигать · Esc снять выбор
```

Это схема размещения, а не требование рисовать рамку. Действуют правила
оболочки: главный экран остаётся без коробки, области разделяют воздух и одна
вертикальная линия. На узком окне документы переносятся под поле; SVG сохраняет
пропорции и квадратную клетку.

Граф рисуется в SVG с `viewBox`, производным от `grid`. Масштаб выбирает клиент;
контент знает только клетки. Узлы — круги с цифрами, линии находятся под ними.
Фон может показывать редкую точечную сетку обычным CSS/SVG-pattern.

Пересечения отмечаются маленьким `×`, их количество показано числом. Сами нити
в спокойном состоянии монохромны. Цвет не кодирует правильность решения.

### Подсветка локальности

У выбранной точки каждая инцидентная нить получает свой цвет. Максимальная
степень точки в контенте — четыре, поэтому достаточно четырёх цветов. Остальные
нити приглушаются.

Каждая окрашенная нить получает двухзначный ID `00`–`11`. В каждой текстовой
полосе тем же цветом и тем же ID отмечается позиция, сопоставленная этой нити.
Номер обязателен: цвет не остаётся единственным каналом связи.

Подсветка принадлежит **позиции**, а не слову, которое сейчас в ней находится.
При перестановке содержимое позиции меняется, её связь с нитью — нет. Позиции,
которые действительно изменились после шага, могут коротко вспыхнуть, но это
дополнительная обратная связь, а не отдельное состояние.

При выборе другой точки подсветка переключается. При повторном нажатии той же
цифры, `Esc`, потере фокуса и победе она исчезает полностью.

### Победа

С последним принятым шагом:

- счётчик меняется на `распутано`;
- выделение точки и цветовая разметка снимаются;
- граф и текст блокируются от дальнейших изменений;
- текст уже находится в авторском порядке;
- появляется тусклая подсказка `Enter`.

Переход не происходит автоматически: игроку нужно время прочитать получившиеся
документы и самостоятельно заметить противоречие. `Enter`, которым могла быть
выбрана другая оболочечная сущность до входа, продолжением не считается;
применяется общее правило `keyup → новый keydown` для полноэкранных состояний.

Новое нажатие исполняет локальный узел из `complete`. Его `set`, `give`, монтаж,
текст и единственный маршрут работают по обычным правилам. Эффекты не выдаются
в момент последнего движения точки: до осознанного продолжения игрок остаётся
на решённой странице.

## Управление

Пока мини-игра активна, её локальный обработчик получает приоритет над
командной строкой и глобальными цифровыми хоткеями.

| Клавиша | Действие |
|---|---|
| `0`–`9` | выбрать точку с таким ID; повтор той же цифры снимает выбор |
| `W` / `↑` | передвинуть выбранную точку на одну клетку вверх |
| `A` / `←` | на одну клетку влево |
| `S` / `↓` | на одну клетку вниз |
| `D` / `→` | на одну клетку вправо |
| `Esc` | снять выбор; если выбора нет — открыть обычное меню оболочки |
| `?` | открыть экран управления поверх мини-игры |
| `Enter` | только после победы: перейти к узлу `complete` |

Поддерживаются верхний цифровой ряд и цифровой блок. Латинские `WASD`
проверяются по `KeyboardEvent.code`, поэтому работают при русской раскладке.
Стрелки отменяют браузерную прокрутку. Удержание клавиши использует обычный
`keydown.repeat`: каждый повтор остаётся отдельным шагом на одну клетку.

До выбора точки клавиши движения ничего не делают. Ход за границу сетки или в
занятую клетку отклоняется без изменения текста. Другие печатные клавиши
игнорируются.

Обработчиков `click`, `pointerdown`, `drag` и `hover` у игрового поля нет. Мышью
по-прежнему можно выделить и скопировать текст документов. Подтип `untangle`
первой версии рассчитан на основной адрес с физической клавиатурой; отдельное
сенсорное управление `/m` в это ТЗ не входит.

## Состояние и сейв

Сейв хранит по ID мини-игры:

```yaml
minigames:
  00-study-ines:
    points:
      0: [21, 11]
      1: [2, 6]
      # ...
    solved: false
    completionApplied: false
```

Сохраняются координаты после каждого принятого шага, `solved` после победы и
`completionApplied` при первом исполнении узла завершения. Выбранная точка,
подсветка, пересечения и переставленный текст — производные и в сейв не
попадают. После перезагрузки они вычисляются из координат и контента.

При первом входе берётся `start`. Повторный вход продолжает сохранённое поле.
Если поле уже решено, сразу показывается восстановленный текст и `Enter`; эффекты
узла завершения повторно не выдаются. Первое нажатие `Enter` на решённом поле
атомарно ставит `completionApplied`, применяет атрибуты узла и входит в него.
После исполнения `complete` дальнейшее поведение определяет исходящий маршрут и
сюжетные флаги. Если уже завершённый файл всё же снова стал целью графа, движок
сразу следует его единственному маршруту без повтора текста и эффектов; в
нормальном прохождении такой вход закрыт установленным сюжетным флагом.

## Валидация контента

Любое нарушение ниже — адресная ошибка сборки с именем файла и поля:

- `id`, `type`, `subtype`, `label`, `grid`, `seed`, `complete`, `points` и
  `threads` обязательны; неизвестные поля запрещены;
- `subtype` равен только `untangle`;
- `columns` и `rows` — целые, координаты `start` и `solution` лежат в сетке;
- точек ровно десять, ID — полный набор `0..9`;
- нитей ровно двенадцать, ID — полный набор `0..11`;
- концы нити существуют, различны; петель и повторов не бывает;
- степень каждой точки не выше четырёх;
- в `start` и `solution` нет совпадающих точек и точки на чужой нити;
- `solution` не содержит пересечений и наложений нитей;
- `start` содержит хотя бы одно пересечение;
- перестановка, созданная `start`, сдвигает не меньше девяти из двенадцати
  позиций полной текстовой полосы;
- до первого `##` есть хотя бы один `###`-документ, и в каждом документе есть
  хотя бы одна полная полоса из двенадцати слов;
- в документе нет запрещённых блочных конструкций;
- узел из `complete` существует в этом файле и имеет ровно один безымянный
  исходящий маршрут;
- ни один другой файл не ссылается напрямую на `#complete`;
- из обычного графа эпизода достижим сам файл мини-игры, а из его завершения —
  допустимая игровая цель.

В `/adm` показываются обе раскладки, число стартовых пересечений, число
затронутых текстовых позиций, список нитей и кнопка локальной проверки решения.
`solution` видна только в авторском интерфейсе.

## Ошибки и граничные случаи

- Совпадающие слова могут скрыть отдельную транспозицию. Это допустимо: победа
  определяется графом, а не сравнением DOM-текста.
- Неполная последняя полоса может не содержать одну из пересёкшихся нитей; в
  таком случае эта пара её не меняет.
- Несколько транспозиций иногда случайно возвращают отдельное слово на исходное
  место. Поэтому валидатор проверяет общую стартовую перестановку, а интерфейс
  никогда не объявляет частичную правильность текста.
- Если после шага пересечений нет, но точка лежит на чужой нити или нити
  накладываются, поле не завершено; проблемная геометрия выделяется цветом
  предупреждения и короткой подписью `разведите точки`.
- Потеря фокуса окна снимает выбор, чтобы после возвращения скрытая точка не
  поехала от стрелки браузерной навигации.

## Реализация

1. Добавить `minigames/` в структуру эпизода, новый тип цели графа и разбор
   frontmatter. Markdown до `## complete` собирать в отдельный список документов.
2. Добавить строгий валидатор схемы и геометрии. `solution` проверять на сервере
   и удалять из клиентского JSON.
3. Реализовать чистые функции `intersections(points, threads)`,
   `textPermutation(original, mapping, intersections)` и `isSolved`. Они не
   должны зависеть от React и порядка пользовательских ходов.
4. Добавить состояние мини-игры в общий reducer и автосейв после принятого шага.
5. Сделать React-рендерер `untangle`: HTML для документов, SVG для поля,
   локальный клавиатурный контроллер и полноэкранное состояние победы.
6. Разнести нынешний `00-study` на диспетчер и три файла мини-игры; третий
   запускать командой компьютера. Сохранить `prolog.study-definitions`,
   `prolog.study-only-case`, `prolog.study-ines` и
   выдачу `word-only-case`.

## Приёмка

- Все три поля подготовки проходятся только цифрами, `WASD` или стрелками и
  `Enter`; мышь не совершает игровых действий.
- Нажатие цифры подсвечивает только инцидентные нити и связанные с ними позиции
  во всех текстовых полосах; повтор цифры и `Esc` полностью снимают разметку.
- Один дискретный шаг меняет текст только при изменении набора пересечений.
- Возврат точки в прежнюю геометрию побитово восстанавливает прежний порядок
  текстовых токенов независимо от пути.
- Авторская `solution` и любая другая корректная планарная раскладка завершают
  поле; граф с нулём пересечений, но точкой на чужой нити — нет.
- После последнего шага текст читается целиком, а переход ждёт нового `Enter`.
- Обновление страницы на середине поля восстанавливает координаты, пересечения
  и текст; обновление на решённом поле возвращает к восстановленному тексту.
- Эффекты `set` и `give` появляются только после `Enter` на решённом поле и не
  дублируются при повторном входе.
- Валидатор отклоняет выход за сетку, дубли точек и нитей, непланарное
  `solution`, слишком слабую стартовую перестановку и внешний переход прямо в
  `#complete`.
- В исходном и собранном клиенте нет обработчиков мыши для мини-игры; тест
  кликает и перетаскивает поле и подтверждает неизменность состояния.
